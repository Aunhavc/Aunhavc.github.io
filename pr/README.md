# ระบบใบขอจัดซื้อ (Purchase Request) — สมใจบิซกรุ๊ป

เว็บแอปสำหรับเปิดใบขอจัดซื้อร่วมกันหลายฝ่าย แล้วพิมพ์ใบ A4 ออกไปให้ผู้บริหารเซ็นอนุมัติ

**ก้อน A (ชุดนี้)** — เปิดใบได้ ปริ้นไปเซ็นได้ครบวงจร
**ก้อน B (ยังไม่ทำ)** — ติดตามสถานะ ปิดงาน export ส่งจัดซื้อ ยกเลิกใบ หน้ารวมผู้บริหาร

---

## ติดตั้ง

### 1. สร้างโปรเจกต์ Supabase ใหม่

ใช้โปรเจกต์**แยก**จาก ADHD Planner โดยเจตนา — ข้อมูลจัดซื้อ ราคา ซัพพลายเออร์ และชื่อผู้บริหาร
ไม่ควรอยู่ปนกับฐานข้อมูลของผลิตภัณฑ์อื่น

### 2. รัน `schema.sql`

Supabase Dashboard → SQL Editor → วางทั้งไฟล์ → Run (รันครั้งเดียว รันซ้ำได้ไม่พัง)

ไฟล์นี้สร้างตาราง สิทธิ์ระดับแถว ฟังก์ชันออกเลขเอกสาร และใส่ข้อมูลตั้งต้น
(9 ฝ่ายพร้อมผู้อนุมัติตามสายงาน · หมวดสินค้ากลุ่ม IT · สาขาตั้งต้น 2 รายการ)

### 3. กรอก `config.js`

```js
SUPABASE_URL:      'https://xxxx.supabase.co',
SUPABASE_ANON_KEY: 'eyJ...'
```

หาได้ที่ Project Settings → API · ทั้งสองค่าเปิดเผยได้ ความปลอดภัยอยู่ที่ RLS ไม่ใช่การซ่อนคีย์

### 4. ปิดการยืนยันอีเมล

Authentication → Providers → Email → ปิด **Confirm email**

ผู้ใช้ล็อกอินด้วยอีเมล + รหัสผ่าน ไม่ต้องส่งอีเมลเลย (Supabase มีข้อจำกัดโควตาอีเมลอยู่)

### 5. ตั้งแอดมินคนแรก

ให้คนแรกสมัครผ่าน `login.html` แล้วรันใน SQL Editor:

```sql
update profiles
   set roles = '{requester,admin}',
       department_id = (select id from departments where code = 'IT')
 where email = 'อีเมลของคุณ';
```

จากนั้นเข้า **ตั้งค่าระบบ** เพื่อกำหนดฝ่าย สิทธิ์ สาขา และหมวดสินค้าให้คนอื่น

### 6. ตั้งเลขเริ่มต้นของแต่ละฝ่าย

ตั้งค่าระบบ → ฝ่าย/สายงาน → ช่อง **เลขเริ่มต้น** ใส่เลขลำดับใบสุดท้ายที่ฝ่ายนั้นเปิดในปีนี้
เพื่อให้เลขรันต่อจากเล่มเดิมโดยไม่ขาดช่วง

## กติกาที่ระบบบังคับ

| กติกา | ที่มา |
|---|---|
| PR เปิดเมื่อยอดเกิน 500 บาท · ผู้จัดการฝ่ายอนุมัติได้ถึง 500 | ข้อความบนฟอร์มเดิมเขียน 2,500 ซึ่งล้าสมัย — `config.js` ตั้งไว้ที่ 500 |
| ผู้บริหารเซ็น **คนเดียว** ตามสายงาน | ฝ่ายที่ approver = `ceo` ขึ้น CEO · `coo` ขึ้น COO |
| ใบสินทรัพย์ต้องมี**รหัสสินทรัพย์จาก SAP ครบ**ก่อนจึงปริ้นได้ | รหัสห้ามซ้ำ — ฐานข้อมูลบังคับ unique |
| อุปกรณ์ IT / กึ่ง IT ต้องผ่านฝ่าย IT ก่อนปริ้น | หมวดสินค้าที่ `is_it = true` ติดธงให้อัตโนมัติ |
| **กดพิมพ์ = ล็อกใบ** แก้ไม่ได้อีก | แก้ได้ทางเดียวคือออกฉบับแก้ไข (Rev.) ซึ่งต้องปริ้นและเซ็นใหม่ทั้งใบ |
| ราคาต่อหน่วยเป็นช่องบังคับ | ผู้บริหารต้องเซ็นยอดจริง ไม่ใช่ยอดประมาณ |
| ยอดที่ใช้ตัดงบ = ยอดหลังส่วนลด **ก่อน VAT** | ไม่หักภาษี ณ ที่จ่ายออก |

การล็อกบังคับที่ฐานข้อมูล (trigger) ไม่ใช่แค่ในหน้าเว็บ — ต่อให้ยิง API ตรงก็แก้ใบที่ปริ้นแล้วไม่ได้

## ใบที่พิมพ์

วางตามฟอร์มกระดาษเดิม `RE15072569 F-HR` ทุกบล็อก — หัวใบ ประเภทเอกสาร เหตุผล ตารางรายการ
วิธีจ่ายเงิน ยอดรวม แถบลายเซ็น 6 ช่อง บล็อกสินทรัพย์ แถบลายเซ็น 5 ช่อง และบล็อกยกเลิก

เพิ่มจากฟอร์มเดิม: **บรรทัดส่วนลด** และ **บรรทัดยอดหลังส่วนลด** (ยอดที่ใช้ตัดงบ)

ใบพอดี A4 หน้าเดียว โดยเหลือที่ว่างประมาณ 15 มม. — ใบที่มีรายการเกิน 9 บรรทัดจะไหลไปหน้าที่ 2
ซึ่งเป็นพฤติกรรมเดียวกับฟอร์มกระดาษเดิม

**ตั้งค่าเครื่องพิมพ์:** A4 แนวตั้ง · ขนาด 100% (ห้าม Fit to page) · เปิด Background graphics
ไม่งั้นแถบเทาของหัวตารางจะหายไป

## ที่ยังไม่ได้ทำในก้อนนี้

ปุ่ม "ส่งต่อแล้ว" และการนับวันค้าง · การอัปโหลดใบสแกนเพื่อปิดงาน · export ชุดส่งจัดซื้อ ·
เลข PO (1 ใบ PR แตกได้หลาย PO) · การยกเลิกใบพร้อมลายน้ำ · หน้ารวมสำหรับผู้บริหาร ·
ปุ่มคัดลอกบรรทัดลงตารางคุมงบ

ฐานข้อมูลเตรียมสถานะ `approved` / `cancelled` และตาราง `pr_log` ไว้รองรับแล้ว
และตัววาดใบรองรับลายน้ำ "ยกเลิก" กับ "ถูกแทนที่" ไว้แล้ว
